# Fabric Guidance

Read the README for the current product status and proposed scope.

- Keep UASF independently usable. Connect to UASH through explicit interfaces.
- Distinguish preserved source records from derived indexes and inferred relationships.
- Do not equate a successful send or resume with proven model exposure or semantic use.
- Use synthetic or reviewed de-identified fixtures; keep secrets and private records out.
- Do not claim UASS compatibility or native-engine support without versioned evidence.
- Keep proposed behavior, implemented behavior, and tested behavior distinct.
- Write self-contained English documentation and record test scope and versions.
- Validate changes in proportion to their scope; documentation checks suffice for
  documentation-only changes.
