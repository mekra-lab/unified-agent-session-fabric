# 개념

## 원본과 세션 식별

원본은 사용자가 명시적으로 등록한 경로나 기록이다.
세션은 그 원본에 속한다.
등록이 다르면 원본 엔진의 ID, 내용 해시, 경로, inode가 같아도 세션을 자동으로 합치지 않는다.
제출된 API 관측은 애플리케이션 대화 참조를 사용할 수 있다. 공급자 세션 ID, 모델 이름, 로컬 파일, 계정 필드는 선택 사항이다.

포착은 원본, 포착 키, 세대, 길이, SHA-256, 세션을 고정한다.
`window`(창), `file_generation`(파일 세대), `native_session`(원본 세션 여부)은 추가 관측을 표현한다.
포착 세대는 고정한 바이트를 식별한다. 파일 계보는 뒤에 내용이 추가되어도 유지될 수 있다.
core ID는 원본·세대·포착·바이트 범위의 정규형 튜플에서 도출한다.
여기에 개체 종류 접두사를 붙인다. 원본 UUID만으로는 UASF 이벤트 ID가 되지 않는다.
파서 버전 문자열을 바꿔도 동일한 바이트 범위는 식별 정보를 유지한다.
버전 문자열만으로 교체 파서의 호환성이 입증되지는 않는다.

Codex 창의 식별 정보는 명시적인 포착 등록에서 온다.
통합은 `Capture.window`를 제공해야 한다.
core는 `session_meta`(세션 메타데이터)의 창 필드나 포착 파일 경로에서 창을 추론하지 않는다.
[Codex 창 등록](reference.md#codex-창-등록)을 참고한다.

## 앵커와 경계

앵커는 `source`, `capture`, `generation`, `file_generation`, `start`, `end`, `sha256`으로 원래 바이트를 식별한다.
각각 원본, 포착, 세대, 파일 세대, 시작, 끝, 해시를 뜻한다.
오프셋은 0부터 시작하는 `[start,end)` 범위다.
완전한 JSONL 레코드에는 끝의 LF(줄바꿈)가 포함된다.
범위 삭제와 증거에는 비어 있지 않은 범위와 소문자 64자리 SHA-256이 필요하다.
창·순번과 원본 UUID 참조는 보조 정보다. 검증된 바이트 앵커를 대체하지 않는다.

조회 경계는 정확한 포착 ID를 순서대로 나열한 목록이다.
분기에 필요한 명시적 부모 포착을 포함해 응답의 관측 범위를 고정한다.
파일 시각과는 무관하며, 최신 파일을 고르는 규칙도 아니다.
정책 의존 관계 집합에는 경계 밖의 소유권 후보도 포함될 수 있다.
삭제된 부모가 다른 포착을 통해 다시 발견되는 일을 막기 위해서다.
정책 의존 관계가 있다고 해서 그 후보들을 응답 이력에 암묵적으로 추가하지는 않는다.

## 관측과 해석

Codex 파생 보기는 창 연결 사슬을 선택한다.
되돌리기로 제외된 항목, 맥락 압축 참조, 경계가 정해진 분기 상속을 유지한다.
부모 순번과 바이트 경계는 일치해야 한다.
분기 경계가 없으면 불완전한 결과를 낸다. 상속에는 명시적 경계가 필요하다.
Claude 파생 보기는 관측된 그래프를 유지한다.
부모 사슬, 논리적 부모, 보존 구간, 요청 참조, 압축 루트가 여기에 포함된다.
압축 루트는 이전 모델 입력을 복구했다는 증거가 아니다.
UUID가 없는 레코드도 물리적 관측으로 남는다. 중복 UUID 후보를 암묵적으로 합치지 않는다.
[인식하는 Claude 유형 18개](reference.md#claude-레코드-유형과-형식-거절) 중 `permission-mode`는 정확히 세 필드인 형식만 지원한다.
관측된 `plan`과 `default` 값은 해석하지 않는 세션 메타데이터다.
다른 문자열 값도 동작 의미를 부여하지 않고 보존한다.
이 레코드는 턴, 계보, 압축, 삭제 의존 관계를 만들지 않는다.
메타데이터 본문에도 일반 삭제 규칙을 적용한다.
알 수 없는 Claude 유형은 포착을 unsupported(미지원)로 만든다(`unsupported_claude_record`).
이력은 이벤트를 유지하고 그래프 계산을 멈춘다.
Codex는 `unsupported_codex_record`를 사용한다.
이는 알 수 없는 레코드를 불투명하게 보존·해석하는 일반 지원이 아니다.

지원되는 API 레코드는 제출된 호출을 나타낸다.
`complete: true`는 해당 호출을 설명할 수 있다. 그래도 대화 전체의 포괄 범위는 알 수 없다.
`app_bytes`로 제출된 바이트와 호출자가 직렬화한 `sdk_json`은 서로 다른 출처 주장이다.
어느 쪽도 공급자의 네트워크 바이트나 모델의 전체 입력을 증명하지 않는다.

## 검증·접근·증거

검증은 반환한 바이트가 고정한 길이·해시 및 적용되는 receipt 연결과 일치한다는 뜻이다.
원래 포착 시점을 인증하거나 모델에 입력이 노출되었다고 증명하지 않는다.
성공한 전송, 참조 해석, 수집, 재개를 모델이 내용을 활용했다는 증거로 격상해서는 안 된다.

파생 보기 상태와 본문 접근은 독립적이다.
상태는 `complete`(완전), `incomplete`(불완전), `unsupported`, `unknown`(알 수 없음), `deleted`(삭제됨) 중 하나다.
본문 접근은 `available`(사용 가능), `blocked`(차단됨), `deleted` 중 하나다.
차단된 본문은 응답에서 null이지만 디스크에 남아 있을 수 있다.
`masked`라는 파생 보기 상태는 없다.
사람이 읽는 라벨은 호환성 필드다. 인가나 검증 판단이 아니다.

증거는 별도로 제출한 사실과 평가로 구성된다.
사실은 `planned`(계획됨), `attempted`(시도됨), `applied`(적용됨), `received`(수신됨),
`exposed`(노출됨), `used`(활용됨), `outcome_unknown`(결과 불명)이다.
평가는 `reported`(보고됨), `candidate`(후보), `observed`(관측됨), `unknown`이다.
사실은 원본별 범위의 증거 ID 아래에서 변경할 수 없다. 자동으로 격상되지도 않는다.
표시 이름은 세션 식별 정보와 별개인 사용자 메타데이터다.
영속 보존과 삭제는 [참조](reference.md#core-등록)와 [삭제](deletion.md)를 참고한다.
