# 운영

## 배포 전제 조건

Linux, 명시적 절대 경로, 수집기가 제어하는 비공개 런타임 루트를 사용한다.
소스 트리는 Cargo 워크스페이스다. 운영자가 사용자·그룹·서비스 관리를 별도로 구성한다.
권한 경계를 시험할 때는 생산자·수집기·소비자 역할을 분리한다.
소비자에게는 gate 소켓을 제공해야 한다.
아카이브 파일, 브리지 직접 접근, 키, 수집기 상태를 제공해서는 안 된다.

gate에는 외부 아카이브 브리지와 이미 설정된 아카이브 수집기가 필요하다.
삭제 조정자에는 신뢰하는 intake·archive 명령이 필요하다.
core·feeder 통합 완료에는 신뢰하는 완료 실행기도 필요하다.
공개 트리는 이 의존 구성요소들의 범용 배포를 제공하지 않는다.
참조 문서의 명령 개요는 구성요소의 인터페이스를 설명한다. 설치는 운영자가 따로 해야 한다.

feeder 키는 신뢰하는 두 역할이 공유하는 비공개 32바이트 파일로 따로 준비한다.
생산자가 쓸 수 있는 수집기 소유의 전달 디렉터리를 사용한다.
정책 디렉터리도 수집기가 소유하며 생산자는 읽을 수 있어야 한다.
상태는 역할별로 비공개로 둔다.
프로세스에 그룹 권한을 임시 부여하면 영구적인 사용자 그룹 가입을 피할 수 있다.
OS 권한은 별도로 설정해야 한다.
소비자에게 전달 디렉터리나 수집기 권한을 절대 부여하지 않는다.
서비스 시작 전에 권한을 검증한다.

## 등록과 포착

정확한 원본 루트와 허용할 상대 파일 또는 원본 JSONL 패턴을 등록한다.
개인 세션의 기본 디렉터리를 암묵적으로 탐색하지 않는다.
원본 루트는 런타임 저장소와 겹치면 안 된다.
feeder와 staging은 심볼릭 링크를 따르지 않고 디렉터리를 탐색한다.
크기를 제한한 두 번의 읽기를 비교해 관측된 변경을 탐지한다.
생산자가 자기 파일을 다시 쓸 수 있는 상황에서 원자적 스냅샷을 보장하는 것은 아니다.

staging은 마지막 완전한 LF까지의 접두부만 게시한다.
불완전한 꼬리 부분은 보류한다. 원본 전체 길이·해시는 receipt에 유지한다.
뒤에 내용을 추가했는지는 이전 접두부 전체를 비교해 분류한다.
교체, 축소, 재작성은 새 파일 계보를 시작한다.
꼬리 부분만 추가되었으면 새 관측을 기록하면서 게시된 세대를 재사용할 수 있다.
feeder는 전송하는 모든 완전한 줄이 중복 키 없는 유효한 JSON 객체일 것도 요구한다.
원본 바이트를 그대로 보존한다.

core 재구축 매니페스트는 고정한 포착을 바이트 공급자에 명시적으로 연결한다.
재구축은 제공된 항목을 등록하고 등록 정보를 처리한다.
기존 등록을 생략해도 삭제되지 않는다.
바이트가 없으면 계속 사용할 수 없다.
뒤에 내용을 추가해도 바뀌지 않은 접두부는 읽을 수 있다.
고정한 접두부가 바뀌면 바이트 제공을 보류한다.
로컬 공급자는 신뢰하는 파일·메모리 어댑터다. 적대적 경로를 안전하게 여는 경계가 아니다.

## 재시작과 복구

사본과 함께 영속 상태도 유지한다.
잠금, 저널, 연결, 삭제 표식, 세대 기록을 지워 실패를 해결하려 하지 않는다.
잠금 디스크립터는 소유 프로세스가 종료되면 해제된다.
삭제 상태가 없거나 잘못되었으면 안전하게 차단한다.

| 구성요소 | 복구 조치와 유지할 조건 |
|---|---|
| Core | 보존한 영속 데이터베이스와 고정한 원본을 사용해 새 파생 인덱스를 재구축. 이름·증거·삭제 정책 유지 |
| Staging | 잠금 아래에서 다시 열거나 inspect. 대기 사본은 활성화 전에 해시 검사. 중단된 재유입 억제 재개 |
| Feeder | 영속 예약한 세대 재시도. 재시작 뒤 승인된 세대를 파일로 생성. 정책 되돌림은 거절하고 추적되지 않은 사본은 제거 |
| Intake | 원래의 원본별 키와 정확한 봉투·페이로드로 재시도. 트랜잭션은 receipt 또는 삭제 표식 유지 |
| Coordinator | `resume` 실행. 작업 ID를 받지 않고, 완료되지 않은 모든 작업을 이어서 처리. 완료 확인된 단계·범위는 건너뜀. 실패한 단계는 대기 유지. 모든 단계가 완료된 작업은 최종 완료 |
| 선택적 큐 | 서비스를 명시적으로 재시작. 휘발성 요청은 재실행하지 않음. 클라이언트는 실패를 확인해야 함 |

core 재구축은 이미 손상된 영속 제출 자료를 이전하거나 복구하는 도구가 아니다.
SQLite 안전 삭제는 저장 매체, 파일시스템 스냅샷, 백업에 대한 보장이 아니다.
파생 데이터를 폐기할 때도 필요한 정책 메타데이터는 보존한다.

## 중지와 철거

새 작업을 막고 서비스를 중지한다. 해당 서비스의 작업자와 리스가 끝날 때까지 기다린다.
실험적 큐는 서비스와 감시 프로세스가 잠금을 해제한 뒤에만 연결을 해제한다.
통합 삭제가 끝났다고 주장하기 전에 대기 중인 삭제 작업을 해결한다.
오프라인 생산자의 사본 제거도 포함한다.
이전에 전달한 바이트는 계속 저장소 제어 범위 밖에 있다.

식별 정보, 사용 중인 사용자·프로세스, 마운트 경계를 확인한 뒤 배포 환경 소유의 런타임 자원만 제거한다.
권한이 높은 정리 작업에서 검증하지 않은 경로를 재귀 삭제하거나 마운트된 파일시스템 경계를 넘어서는 안 된다.
권한이 필요한 철거 스크립트는 공개 제품 설치 프로그램으로 제공하지 않는다.
시작 예시는 대신 자신이 새로 만든 비공개 합성 디렉터리만 제거한다.
