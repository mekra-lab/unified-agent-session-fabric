이 문서는 [영어판](../security-and-limits.md)의 번역이며, 내용이 다르면 영어판이 우선한다. 번역 기준 버전: **0.1.0**(Rust 크레이트 선언 버전).

# 보안과 한계

## 신뢰 경계

수집기, 설정된 실행 파일, 원본 등록, 런타임 상태는 신뢰하는 대상이다.
intake CLI 인자로 전달한 principal(주체)은 네트워크 호출자를 인증한 결과가 아니다.
원본 소유자는 자기 원본을 바꿀 수 있다. 서명 권한이 있는 소유자는 오해를 부르는 내용에도 서명할 수 있다.
검증은 바이트와 receipt의 일치를 확인한다. 포착 시점의 진실성이나 모델에 입력이 노출되었는지 확인하지 않는다.
합성 예시는 생성한 데이터만 사용한다.

feeder/staging은 디스크립터를 기준으로 파일을 열 때 심볼릭 링크와 일반 파일이 아닌 대상을 거절한다.
feeder는 inbox 소유권, 권한 모드, 하드 링크, 서명, 정규화된 경로, 순서, 선행 항목도 검사한다.
gate는 신뢰하는 디렉터리의 소유권·권한 모드, 소켓 모드, receipt 연결을 검사한다.
외부 브리지 프로세스에는 비공개 `TMPDIR`을 사용한다.
core 로컬 공급자는 명시적으로 지정한 신뢰하는 파일 경로를 사용한다.
feeder/staging의 안전한 파일 열기를 대체하지 않는다.
소비자는 비공개 SQLite 파일과 영속 정책을 수정해서는 안 된다.

gate는 소켓 모드 0600 또는 0660을 허용한다.
소켓 상위 디렉터리는 gate UID가 소유해야 한다. 그룹 쓰기 권한은 없어야 한다.
그룹에 전달할 때는 적절히 설정한 setgid 디렉터리를 사용한다.
원본·staging·삭제 접수 검사는 내용 제공 전에 수행한다.
gate의 읽기 스냅샷은 무기한 전달 리스가 아니다.
이전에 전달한 응답은 회수할 수 없다.

## Core 한계

MiB와 GiB는 이진 단위다.
다음은 강제되는 상한이며 **지연 시간, RSS, 처리량 보장이 아니다**.
조회 범위에는 응답 집합과 거기서 이어지는 정책 의존 관계 전체가 포함된다.
의존 관계를 여러 포착으로 나눠도 제한을 피할 수 없다.

| 상한 | 적용 범위 | 거절 결과 |
|---|---|---|
| 32 MiB | 로컬 공급자의 고정된 접두부 하나 | 바이트 사용 불가 또는 검증 미지원 |
| 레코드 10,000개 | 잘못되었거나 미완료인 레코드를 포함해 조회에 필요한 물리적 레코드. 빈 포착은 1개로 계산. 사용 불가 데이터는 길이에 따른 보수적 상한 사용 | `query_record_limit` |
| 간선·탐색 단계 20,000개 | 저장·예약한 간선과 의존 관계 탐색 | `query_edge_limit` |
| 부모 이동 128회 | 분기 부모를 포함한 포착 계보 | `query_depth_limit` |
| 64 MiB | 저장된 JSON을 메모리에 구성하는 용량 한도 | `query_materialization_limit` |
| 후보·정책 방문 10,000회 | 범위가 정해진 소유권·정책 조회 | `query_policy_limit` |
| 256 MiB | 직렬화한 writer JSON 응답. CLI 끝의 LF는 제외. 각 익명 스풀에도 적용 | `query_output_limit` 또는 `query_spool_limit` |
| 접수한 조회 2개 | 연결되지 않은 core CLI. 영속 저장소 상위 디렉터리별 적용 | `query_capacity_exceeded` |
| 주소 공간 1.5 GiB | 접수한 각 비연결 core CLI 조회 프로세스 | 커널 할당 실패는 정상적인 거절 응답이 아님 |
| 요청 1 MiB | 비연결 core 조회의 stdin 입력 경로 | `query_request_limit` |

파생 보기를 만든 뒤 정확한 직렬화 길이를 검사한다.
반복되는 모든 앵커를 포함해 실제 출력 필드만 계산한다.
256 MiB를 처음 넘기는 항목을 더할 때 멈춘다. 정확히 256 MiB는 허용한다.
조회를 다시 실행하지는 않는다.
최종 스풀은 전달 전에 자체 절대 상한과 계산 완료된 길이의 일치를 별도로 검사한다.
이 검사는 파생 보기를 만든 뒤에 이루어진다.
비용이 낮은 접수 검사도, 파생 보기 메모리 사용량 상한도 아니다.
인덱스 디렉터리에서 Linux `O_TMPFILE`을 지원해야 한다.
라이브러리를 직접 호출하는 측은 자체 접수 정책을 책임진다.
주소 공간 제한은 RSS 상한이나 호스트 전체 제한이 아니다.
기본 비연결 core 경로에서 인라인 `--json`은 stdin 크기 방어를 사용하지 않는다.
명시적으로 선택하는 큐 클라이언트는 stdin과 인라인 입력 모두에 요청 상한 1 MiB를 별도로 검사한다.

sources는 자신의 전체 범위를 나열한다.
sessions는 요청한 원본 전체 또는 저장소 전체를 나열한다.
evidence는 요청한 원본·세션을 나열한다.
목록은 용량 한도를 넘을 수 있다.
어떤 작업도 일부를 조용히 잘라 성공한 부분 응답으로 반환하지 않는다.
조회 범위의 준비 정보가 없으면 `index_requires_rebuild` 또는 `query_scope_unavailable`을 반환한다.
상태는 `incomplete`이며 데이터는 비어 있다.
[응답 규칙](reference.md#응답과-오류)을 참고한다.

## 다른 구성요소의 한계

| 구성요소 | 제한과 동작 |
|---|---|
| Staging | 원본 전체 읽기는 최대 32 MiB. 초과하면 미지원이며 잘라서 포착하지 않음 |
| Feeder | 원본과 inbox 레코드 전체는 최대 32 MiB. 헤더는 최대 16 KiB. 헤더 크기 때문에 32 MiB 원본이 레코드 상한 안에 들어간다는 보장은 없음 |
| 공통 JSON | 최대 깊이 128. 비유한 부동소수점 수, 오버플로, 잘못된 UTF-8/유니코드, 뒤에 붙은 입력 거절 |
| Gate I/O | 요청 1 MiB, 응답 65 MiB. 일반 `serve` 소켓 I/O는 5초, `query` 클라이언트 I/O는 300초. 브리지 실행 기한은 60초 |
| Gate 주소 공간 | `serve`와 `check-local`은 일반·스케줄링 실행 전에 주소 공간을 768 MiB로 제한. 브리지 자식은 프로세스별로 이를 상속. `query` 클라이언트는 이 제한을 설정하기 전에 반환 |
| 일반 gate 접수 | staging 루트당 슬롯 2개. 일반 `serve`만 서버 수명 동안 슬롯 유지. 일반 `check-local`은 응답 완료까지 하나 유지 |
| 스케줄링된 gate 접수 | 프런트엔드는 서버 수명 동안 실행 슬롯을 잡는 대신 각 요청을 선택적 큐로 전달. 대기 요청은 실행 슬롯·삭제 잠금 없음. 큐 접수·기한 규칙을 적용하고 실행 시 작업자가 검사 |
| 조정자 | 요청 1 MiB, 외부 출력도 제한. 외부 실행 시간 제한 기본값은 90초이며 1 ms~3,600,000 ms로 설정 가능 |
| 선택적 큐 | 실행 중 2개, 대기 32개, 원본별 대기 16개. 입력부터 전달까지 절대 기한 8초. 표본 측정한 합산 RSS가 1 GiB를 넘으면 취소 |

큐의 표본 측정은 커널이 강제하는 절대 상한이 아니다.
큐는 성능 승인 기준을 충족하지 못했다.
원본 연결 사슬, 중복 참조, 앵커가 많이 반복되는 큰 배열은 원본 바이트 상한에 이르기 전에도 조회 한도를 소진할 수 있다.
시간 측정 시험에서 처리한 작업량이 지원 최대치를 보장하지는 않는다.

## 실패와 실험 기능 제한

삭제 검사는 일치, 불일치, 확인 불가의 세 결과를 낸다.
적용되는 텍스트·세션 규칙이 있는데 데이터를 디코딩할 수 없으면 포착·제출을 보류한다.
파싱 실패는 절대 불일치의 증거가 아니다.
staging은 `deletion_inspection_unavailable`을 보고한다.
intake는 `deletion_state_unavailable`로 안전하게 차단한다.
조정자의 대상 계획은 검사 실패를 거절한다.
넘치는 숫자나 깊게 중첩된 필드와 함께 있는 이스케이프 문자열에도 이 규칙을 적용한다.
일반 JSON 표식 키는 일반 객체의 키로 남는다.

page probe는 core 정책이 차단한 본문을 노출할 수 있다.
page probe와 index probe는 합성 데이터 전용 도구이며 운영 설치에서 제외한다.
소비자에게 노출하거나 실제 기록에 사용하지 않는다.
현재 core 제한은 그대로 적용된다. probe는 승인된 페이지 나누기 서비스를 정의하지 않는다.
